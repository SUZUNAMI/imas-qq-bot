# 爱马仕官方新闻 QQ 转发机器人 — 架构与部署计划

> 状态：v2 决策已确认（NapCatQQ + DeepSeek + Python + 文字图片 + 专用小号）
> 目标：追踪 https://idolmaster-official.jp/news 更新，新新闻发布后把「原文 + AI 翻译」推送到 QQ 群。
> 部署路径：本地（Windows）→ 迁移 Windows Server。

---

## 1. 目标与范围

- **输入**：idolmaster-official.jp/news 新闻列表页 + 每条新闻详情页。
- **处理**：检测新增新闻 → 提取原文（标题+正文+配图）→ AI 日译中。
- **输出**：推送到一个或多个 QQ 群（原文 + 译文 + 链接 [+ 配图]）。
- **非目标**：不做历史新闻回填（首跑只记录现状、不轰炸）、不做多账号、不做消息撤回/编辑同步。

## 2. 现状调研结论

| 项 | 结论 |
|---|---|
| 站点 | Bandai Namco 自有 CMS，非标准 WordPress |
| 详情 URL 模式 | `https://idolmaster-official.jp/news/01_17821`（数字 ID） |
| 列表分页 | `/news/page/N` |
| RSS | 主站 idolmaster.jp 有 `/blog/?feed=rss2`，但 `/news` 页 RSS 待确认（很可能无） |
| 结论 | 采用 **HTML 抓取 + 增量检测** 为主，RSS 作为可选备选（若有则优先） |

> 注：编写本文档时沙箱无法出站访问该站点，HTML 具体选择器（列表项/标题/日期/正文的 CSS 路径）在实现阶段第一步「抓取探针」中确认并固化到配置。

## 3. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        采集层 (Collector)                      │
│  定时调度器 ──► 页面抓取 ──► 列表解析 ──► 增量检测(对比SQLite)   │
└───────────────────────────────┬─────────────────────────────┘
                                │ 新增条目(URL唯一键)
┌───────────────────────────────▼─────────────────────────────┐
│                        处理层 (Processor)                     │
│  详情页抓取 ──► 正文提取 ──► AI 日译中 ──► 消息组装             │
└───────────────────────────────┬─────────────────────────────┘
                                │ 结构化消息(原文+译文+链接+图)
┌───────────────────────────────▼─────────────────────────────┐
│                        推送层 (Notifier)                      │
│  OneBot11 适配 ──► QQ Bot ──► 群1 / 群2 / ... / 群N          │
└───────────────────────────────┬─────────────────────────────┘
                                │
                     ┌──────────▼──────────┐
                     │  SQLite 状态/日志    │
                     │  seen_items / logs  │
                     └─────────────────────┘
```

**数据流**：定时触发 → 抓列表 → 解析条目 → 与 `seen_items` 对比 → 有新增 → 抓详情 → 翻译 → 组装 → 发群 → 写入已见集合 → 等待下一轮；无新增则直接结束。

## 3.5 模块化交付

本线程只负责架构。可独立交接的模块、数据契约、并行顺序见 **`docs/module-specs.md`**（交接文档）。模块拆分：M1 列表抓取 / M2 详情解析 / M3 增量检测 / M4 翻译 / M5 消息组装 / M6 QQ推送 / M7 主控调度 / M8 配置 / M9 打包迁移。

> 探针结论（2026-08）：列表页为 Next.js SPA，列表数据客户端拉取、无 RSS/sitemap；详情页 `__NEXT_DATA__` 有内容可直接解析。

## 4. 模块设计

### 4.1 更新探测器（fetcher / detector）
- 语言/库：`httpx`（请求，带 UA + 重试退避）+ `BeautifulSoup`（解析）。
- 调度：`APScheduler` 内部常驻调度，默认 **5 分钟** 一轮（可配置）。
- 抓取范围：首页 + 前 2 页，防漏。
- 唯一键：新闻详情 **URL**（如 `01_17821`）作为幂等键。
- 增量逻辑：`seen_items(id, url, title, date, first_seen_at, pushed_at)`；`url NOT IN seen` 即新增。
- 反爬/容错：连接失败重试 3 次指数退避；解析失败记录日志并告警，不中断。

### 4.2 详情提取（extractor）
- 抓详情页 → 提取标题、发布日期、正文（去 HTML 标签、保留换行）、配图 URL（可选）。
- 选择器配置外置，站点改版时只改配置不改代码。

### 4.3 AI 翻译（translator）
- 调用 LLM Chat API，system prompt 固化「专业日译中、保留格式、术语规范」。
- 输入：标题 + 正文纯文本；输出：标题译文 + 正文译文（结构化）。
- 可选术语表（JSON，如 アイドルマスター→偶像大师 等专名），随 prompt 注入。
- 成本：单条新闻数百字，DeepSeek/百炼 每条 < ¥0.01。

### 4.4 消息组装（formatter）
- 模板（原文与译文均拼接，2026-08-26 v2）：
  ```
  【NEWS】<发布日期>
  <原标题>

  <原文正文>

  ——— 中文翻译 ———
  <标题译文>
  <正文译文>

  🔗 原文：<链接>
  ```
- 超长正文分片发送（避免单条消息过长）。
- 配图（可选）：转 OneBot `[CQ:image]` 或图片 URL。

### 4.5 QQ 推送（notifier / bot）
- 协议：OneBot 11（HTTP / 反向 WebSocket）。
- 多群：遍历配置 `groups: [群号1, 群号2, ...]` 顺序推送，单群失败不阻断其他群。
- 发送频率控制：群间加小间隔，降低风控概率。

### 4.6 状态与日志（storage）
- SQLite 单文件：`state.db`（seen_items + push_log）。
- 运行日志：`logs/app.log`（按天轮转）。
- 幂等：推送成功后才写 `pushed_at`，失败下次重试不重发（事务保证）。

## 5. 技术栈选型（推荐默认）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.11+ | 生态成熟、Windows 原生、迁移简单 |
| 抓取 | httpx + BeautifulSoup | 轻量稳定 |
| 调度 | APScheduler | 单进程内调度，无需外部 cron |
| 存储 | SQLite | 零部署、单文件易备份迁移 |
| 配置 | YAML + 环境变量 | 密钥/群号外置，不进 git |
| QQ 接入 | **NapCatQQ（OneBot 11）** | 需登录 NTQQ 客户端，官方客户端登录封号风险低 |
| 翻译 | **DeepSeek** | 便宜、日中翻译质量好 |
| 推送内容 | 文字 + 图片 | 原文+译文+链接+新闻配图 |

## 6. 实施计划（分阶段，每阶段验收后再进下一步）

| 阶段 | 内容 | 验收标准 | 预计耗时 |
|---|---|---|---|
| P0 需求确认 | 确认 QQ 接入/翻译服务/推送范围/账号 | 决策落定，更新本文档 | 本轮 |
| P1 抓取探针 | 抓取列表+详情，确认 HTML 选择器，写出解析脚本 | 能打印出最近 10 条新闻（标题/日期/URL/正文） | 1 次会话 |
| P2 增量检测 | 落库 SQLite，实现增量对比 + 去重 | 重复运行不重报，新增能识别 | 1 次会话 |
| P3 翻译接入 | 接 LLM API，术语表，结构化输出 | 原文+译文正确生成 | 1 次会话 |
| P4 QQ 推送 | 装 bot 框架，接 OneBot，推送到测试群 | 测试群收到「原文+译文」消息 | 1–2 次会话 |
| P5 稳定化 | 日志、异常重试、防重发、失败告警、长时间运行 | 连续运行 24h 无重复/无漏报 | 视情况 |
| P6 打包迁移 | WinSW 打包 Windows 服务，配置/密钥外置，备份状态库 | Windows Server 开机自启、可迁移 | 视情况 |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| QQ 封号/风控 | 用官方客户端登录(NapCat)相对安全；控制频率；建议专用小号 |
| 站点反爬/改版 | 选择器配置外置；解析失败告警并人工介入 |
| 翻译质量不稳定 | 术语表 + prompt 调优；保留原文兜底 |
| 重复/漏推送 | URL 幂等键 + 事务；失败重试不重发 |
| 服务器迁移 | 状态库随迁备份；NapCat 需在服务器首次交互登录后常驻 |
